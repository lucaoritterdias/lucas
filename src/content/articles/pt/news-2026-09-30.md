## Agentes deixam de esperar pelo próximo prompt

A OpenAI apresentou o **Dots**, uma proposta de agentes permanentes que trabalham em um computador na nuvem, conectam-se a aplicativos e continuam executando objetivos em segundo plano. A mudança mais importante não é uma nova interface de conversa: é a passagem de uma IA reativa para uma operação contínua.

Para empresas, isso aumenta a importância de permissões mínimas, trilhas de auditoria e pontos explícitos de aprovação. Quanto mais tempo um agente trabalha sem supervisão direta, mais importante se torna definir não apenas o que ele pode fazer, mas quando deve parar.

[Ler o anúncio da OpenAI](https://openai.com/index/introducing-dots/)

## IA encontra 24 vulnerabilidades no Android

O GitHub detalhou como seu agente aberto de segurança encontrou **24 vulnerabilidades em projetos Android**, incluindo falhas consideradas críticas. O trabalho combina fluxos especializados, fuzzing e revisão humana em vez de tratar o modelo como um scanner genérico.

O caso aponta para um uso mais concreto de agentes em engenharia: tarefas estreitas, verificáveis e com um resultado que especialistas conseguem reproduzir. A qualidade não vem apenas do modelo, mas do ambiente de teste e das ferramentas colocadas ao redor dele.

[Ler a análise no GitHub Blog](https://github.blog/security/how-we-found-24-android-vulnerabilities-using-our-open-source-ai-security-agent/)

## Git 2.56 chega com melhorias para o trabalho diário

O projeto Git lançou a versão **2.56**, e o GitHub publicou um panorama das mudanças mais relevantes. Atualizações desse tipo raramente parecem grandes isoladamente, mas afetam uma ferramenta que está no caminho crítico de praticamente todo time de software.

A recomendação prática é simples: antes de atualizar ambientes compartilhados, confira mudanças de comportamento, compatibilidade com hooks e ferramentas que interpretam a saída do Git. Uma melhoria pequena no terminal pode gerar diferenças em automações antigas.

[Conhecer os destaques do Git 2.56](https://github.blog/open-source/git/highlights-from-git-2-56/)

## GitHub leva o HydraFusion ao VS Code e ao Copilot

O GitHub anunciou a chegada do **HydraFusion** ao VS Code e ao aplicativo do GitHub Copilot. A novidade reforça uma tendência visível nas ferramentas de desenvolvimento: recursos de IA estão deixando de viver numa janela isolada e passando a participar diretamente da superfície onde o trabalho acontece.

Essa integração reduz troca de contexto, mas também aumenta o cuidado necessário com o que entra no contexto do agente. Repositórios, terminais e credenciais convivem muito perto uns dos outros; conveniência e controle precisam evoluir juntos.

[Ver a publicação no GitHub Changelog](https://github.blog/changelog/2026-09-30-hydrafusion-in-vs-code-and-the-github-copilot-app/)

## Empresas de IA assinam acordo voluntário de segurança

Líderes de grandes empresas de tecnologia assinaram nos Estados Unidos um acordo voluntário que prevê revisões internas e externas de sistemas de IA. Segundo a cobertura da Associated Press, os detalhes completos ainda não estavam disponíveis no momento da publicação.

O ponto para acompanhar é como compromissos gerais serão convertidos em mecanismos verificáveis: quem audita, quais incidentes precisam ser divulgados e quais consequências existem quando os controles falham. Sem respostas objetivas, autorregulação corre o risco de permanecer apenas uma declaração de intenção.
